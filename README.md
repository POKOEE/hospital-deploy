Цель работы
Освоить процесс переноса готового веб-приложения из среды разработки в продакшен-среду. Отработать навыки контейнеризации (Docker), настройки обратного прокси (Nginx), обеспечения безопасности (HTTPS), работы с переменными окружения и настройки CI/CD пайплайнов (GitHub Actions).


В рамках работы была настроена следующая схема :


Nginx (Единая точка входа): Принимает все внешние запросы, обрабатывает SSL и распределяет трафик.

Бэкенд (API): Запросы к /api/ перенаправляются на внутренний сервис (Gunicorn/Uvicorn для Python или Node.js).

Фронтенд: Статические файлы (React/Vue) отдаются напрямую через Nginx.

База данных (БД): (Если применимо) запускается в изолированном контейнере и доступна только бэкенду.

Что было сделано 
1. Подготовка к продакшену
Выполнена продакшен-сборка фронтенда (npm run build).

Проверена сборка на отсутствие ошибок импорта.

Бэкенд переведен с серверов разработки (Flask app.run(debug=True), nodemon, uvicorn --reload) на продакшен-серверы (Gunicorn, node, uvicorn без reload).

Настроены файлы .gitignore и .dockerignore для исключения попадания секретов и лишних файлов в репозиторий и Docker-образ.

2. Работа с переменными окружения и секретами
Вынесены адреса сервисов, пароли БД и ключи API из исходного кода в переменные окружения.

Создан файл .env (не коммитится в Git) и .env.example (шаблон для команды).

Разделены переменные этапа сборки (например, VITE_..., видимые в браузере) и переменные этапа запуска (секретные ключи, доступные только на сервере).

3. Docker и Docker Compose
Написаны/доработаны Dockerfile для каждого сервиса с использованием многоэтапной сборки (multi-stage build) для уменьшения размера итоговых образов.

Настроен запуск процессов внутри контейнеров от имени непривилегированного пользователя (USER).

Все сервисы (frontend, backend, nginx, db) описаны в едином файле docker-compose.yml.

Настроены тома (volumes) и зависимости (depends_on).

4. Настройка Nginx и HTTPS (SSL)
Nginx настроен как обратный прокси-сервер (proxy_pass).

Настроена передача заголовков X-Forwarded-For и X-Forwarded-Proto.

Настроен редирект с HTTP на HTTPS.

С помощью утилиты mkcert выпущен локальный SSL-сертификат для домена *.localhost.

Сертификаты (hospital.localhost.pem, hospital.localhost-key.pem) подключены к Nginx. Примечание: приватные ключи и сертификаты не коммитятся в репозиторий.

5. CI/CD (GitHub Actions)
Доработан workflow в .github/workflows/ для проверки сборки Docker-образов при каждом пуше в репозиторий (Continuous Integration).

Добавлены секреты репозитория для доступа к GitHub Container Registry (GHCR).

Настроена логика сборки и доставки образов (Continuous Delivery).

Добавлена возможность ручного запуска workflow (workflow_dispatch).
